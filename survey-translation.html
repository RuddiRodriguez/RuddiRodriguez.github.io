Make multilingual survey material easier to analyse

Survey work involves more than translating a paragraph. Responses sit inside data tables, questions appear as column labels, and questionnaire text lives in structured files. Analysts need the translated material to remain connected to its original variables.

I built a Python prototype for translating SPSS survey files and XML questionnaires into English. Alongside it, I explored searching survey variables by meaning: asking for a topic instead of remembering a column identifier.

This entry follows the reviewed implementation. Excerpts are shortened, anonymised adaptations; client names, project identifiers, real survey content, local paths, and connection secrets are omitted. They explain the main operations rather than provide a complete application.

Two translation routes and one separate search experiment

The command-line entry point takes a file path and sets English as the target language. A batch script processes matching files in a folder; another provides a folder-selection interface. The Streamlit web page accepts an uploaded SAV or XML file, runs the same processor, and offers the translated file for download.

The search experiment reads SPSS labels directly. It is not an automatic stage after translation and is not exposed through the reviewed translation page.

Choose a processor without changing the calling workflow

Each processor knows its file format. The caller supplies a file and language settings; the processor reads, translates, and exports it. A missing source language lets the active Google translator detect the language.

The archived factory also names a DOC processor, but that class is a placeholder rather than a working Word translator. The web interface accepts only SAV and XML.

Translate likely response columns and their labels

An SPSS file contains a data table plus information describing its variables. The processor reads both with pyreadstat, copies the table, and identifies columns that appear to contain natural-language text.

Selection uses the first non-empty string in each text column. It looks for letters, excludes obvious technical values such as screen-resolution patterns or browser names, and skips identifier fields. This is a practical heuristic, not a trained detector of open-ended survey answers.

select_response_columns summarises the selection helpers in this excerpt. Once selected, non-empty text values are translated. Numeric columns are not sent for translation.

The response translation and column-label translation run as two concurrent tasks. The writer passes the translated column labels into the new SAV file.

The current processor exports only the first 20 data rows. It also passes column labels rather than explicitly restoring every part of the original SPSS metadata, such as value labels and missing-value rules. Preserving all SPSS information would require additional work.

Translate selected questionnaire elements

The XML route parses the questionnaire as a tree, then visits header, question, and answer elements. It replaces their text and writes a new UTF-8 XML document.

The original helper also cleans particular formatting markers, splits text on “. ”, translates the resulting pieces, and joins them again. The excerpt isolates the core traversal and replacement.

This translates the selected elements’ direct text. It does not promise complete handling of nested formatting, element-tail text, or every possible questionnaire structure. XML serialisation can also change the original formatting.

Three translation methods explored

MethodHow it worksRole in this project
Google TranslateSends text to Google’s translation service through a Python wrapper; detects the source language when omitted.Active method for SPSS text, column labels, and XML text.
M2M100Uses a pretrained multilingual translation model and tokenizer locally, with explicit source and target language codes.Alternative helper and benchmark route.
GPT-3.5 TurboAsks a language model to translate text through a system instruction and user message.Alternative helper and benchmark route using the archived OpenAI SDK.

The selected local checkpoint is facebook/m2m100_418M. Its language-token setting tells the model which language to generate. The project uses pretrained weights; it does not train a translation model.

These alternatives are present in the source, but the active SAV and XML paths call Google Translate. The SAV method still loads M2M100 even when Google performs the translations, adding unnecessary model-loading overhead.

Record translation timing with MLflow

A separate benchmark selects a translation method and times processing for each selected column. It records the method, column, number of rows, and elapsed time in MLflow backed by a local SQLite database.

Timing records help inspect workload and execution speed. They do not measure meaning preservation, fluency, or translation accuracy. The reviewed repository does not provide a verified quality ranking of these methods.

There is also a benchmark defect: the GPT branch selects missing values instead of non-empty text. That prevents treating its recorded workload as a fair comparison without correction and a fresh run.

Find survey variables by meaning

Survey column identifiers are often difficult to remember. Semantic search addresses a different task from translation: given a phrase such as “Household members”, retrieve labels that describe a similar topic even when the wording differs.

The PyTorch script reads the SPSS mapping between column names and labels. It combines each label with its identifier, converts the text into a numerical vector, and adds those vectors to an Annoy search index.

The selected model is sentence-transformers/multi-qa-mpnet-base-dot-v1. The code loads it through Hugging Face’s tokenizer and model classes and uses the first token’s final representation as the text vector.

Nearby vectors suggest related variables. The returned distances rank similarity; they are not calibrated probabilities that a variable is correct. The script prints matching labels and their identifiers rather than generating an answer or translating them.

The original script requests CUDA directly, so its device setup assumes a compatible GPU. It can load an existing index, but the mapping from index positions to labels must remain consistent. Building an index and reliably packaging it for reuse are separate concerns.

Related scripts extract question identifiers and text from questionnaire XML into a dictionary. TensorFlow and commented LangChain experiments also exist. They are separate explorations, not evidence that the web app provides an integrated questionnaire-search service.

A web interface and an Azure deployment configuration

The Streamlit page writes an uploaded file temporarily, calls the selected processor, and offers the resulting file for download. Input and translated temporary files are then removed by the application flow.

GitHub Actions is configured to install dependencies with Python 3.10 and deploy the packaged application to Azure App Service when the main development branch is updated. Deployment credentials are referenced through repository secrets; no real app identifiers or credential references appear in these excerpts.

The fuller development repository contains documentation, notebooks, an extracted dictionary, and an index reference. Its smaller deployment copy shares the same application source. That copy is not a different translation algorithm.

Reviewing deployment configuration does not establish that a live service is currently available. This article documents the implementation; I have not rerun translation, benchmarked the services, or checked a deployed instance for this entry.

What the prototype demonstrates

The project connects file handling, text selection, translation, and export in a reusable workflow. It also explores a useful extension: finding survey variables through their meaning.

The main boundaries matter when interpreting it:

  • The SPSS application path processes 20 rows, not a complete survey export.
  • Text-column selection relies on an example value and can include or exclude the wrong column.
  • The response translation cache is recreated inside each call, so repeated responses do not benefit from a persistent cache.
  • Export passes translated column labels without explicitly preserving every SPSS metadata field; cleanup can also alter original text.
  • XML translation covers selected direct-text elements rather than arbitrary structured documents.
  • Benchmarks record elapsed time, with no validated translation-quality or search-relevance results.

These limits describe the reviewed code. The public excerpts make its most useful ideas inspectable while keeping private survey material outside the portfolio.
