PERSONAL TOOL / LLM CLASSIFICATION / PYTHON

Saved videos.
Sorted by what they are about.

I save Instagram videos to watch later and never find them again. I built a tool that downloads my saves and files them into topic folders. The first version grouped the videos by language rather than subject. Letting a language model read each video on its own fixed that.

By Ruddi Rodriguez Garcia · Personal project · 8 November 2026

A folder of good intentions

Instagram's “saved” tab is where useful videos go to disappear. Mine had volleyball drills, recipes, programming tips, machine-learning explanations, finance clips and a long tail of random things, all mixed together in one endless scroll with no search.

I wanted an ordinary folder on my computer: one subfolder per topic, each video next to a small note with its caption, tags and original link, plus a spreadsheet index. I did not want to define the topics myself. The tool should find them in what I had actually saved.

Five steps, each one resumable

The tool is a Python command-line app, igvault. Each step writes its output to disk, so it can be re-run without repeating finished work:

StepWhat it does
collectDownloads saved video posts and their metadata from my account.
indexNormalises the metadata into one record per video: caption, hashtags, author, duration, file paths.
transcribeOptional speech-to-text with Whisper. It was not installed for this run, so nothing used transcripts.
classifyDecides the topic folders and puts each video in one of them. Most of this article is about this step.
organizeCopies the videos into library/<Topic>/ and writes a Markdown note per video, a CSV index and a README.

First attempt: embed, cluster, name

The first classifier followed the textbook unsupervised recipe. Each video became a short document (caption, hashtags, transcript). An embedding model turned each document into a vector, k-means grouped the vectors into clusters, and a language model read a few examples from each cluster and gave it a name, a description and a list of tags.

The folder names looked convincing: Volleyball Training Tips, Batch Cooking Ideas, Cuban Literature and Poetry, Investment Strategies and Tools. The contents did not. When I opened the folders, many videos had nothing to do with the folder name, and their tags were often unrelated to the video.

Why it failed

Looking at individual videos showed four separate causes:

  • Language mixed in with topic. About a quarter of my saves have Spanish captions. Caption embeddings place Spanish texts close to each other, so a Spanish fruit advert and a Spanish language lesson ended up together in the “Cuban Literature” cluster.
  • Every video had to join a cluster. K-means has no “none of these” option. With the number of clusters fixed at ten, a home chest workout, a running guide and a general health clip were all placed in the nearest cluster, which was volleyball.
  • Tags belonged to the cluster, not the video. All 283 videos shared just 11 tag lists. One wrong video in a cluster was enough to make the tags wrong for others.
  • Many captions said almost nothing. About a third of the videos had captions that were just emojis, a few hashtags or a sales slogan. With no transcripts, the vectors for these videos carried almost no information.

None of these problems could be fixed by tuning the clustering. The method was comparing the wrong thing: how similar the caption texts were, instead of what each video was about.

Second attempt: read every video first

The new classifier puts the language model at the start of the process instead of the end. It works in three passes:

  1. Describe. The model reads each video's caption, hashtags and author, in batches of twelve, and writes a one-sentence English summary, a broad subject and three to six tags specific to that video. Because the output is always in English, the original language no longer matters. When a caption has fewer than about twelve real words, the tool uses ffmpeg to take three frames from the video and sends them to the model as well. That applied to 91 of the 283 videos.
  2. Design the folders. All summaries go to the model in one request, together with a count of how often each subject appears. It proposes a set of folders under explicit rules: merge related subjects, never group by language or by whether a video is an advert, and keep “Other” small.
  3. File. Every video is assigned to exactly one folder, or to “Other”, with a confidence score. If more than about 8% end up in “Other”, the model proposes extra folders for just those videos and they are filed again.

Descriptions are cached per video, so later runs only describe newly saved videos. The old clustering method is still there as an offline fallback for when no model is available.

Results compared

I had no labelled data, so I measured the improvement in two simple ways. First, I took a random sample of 45 videos (fixed seed) and checked each assignment myself, before and after the change. Second, I counted how varied the tags were across the whole library.

The misfiled videos in the first version were not borderline cases: workout videos filed under volleyball, a health wristband under investing, a fruit advert under literature. The final folders are Volleyball, AI & Machine Learning, Programming & Software, Cooking & Meal Prep, Men's Style & Grooming, Arts & Entertainment, Fitness & Exercise, Finance & Investing and five smaller ones.

The bigger “Other” share is a deliberate trade-off. The new version would rather say “this does not fit” than force a video into the nearest folder.

Limits

The 45-video check is my own judgement, with a single reviewer and no labelled reference. It shows a large and obvious difference, but it is not a benchmark. “Clearly misfiled” means a video whose subject did not match its folder at all; I did not count borderline cases such as a sorting-algorithm animation filed under machine learning.

The folder list comes from the model and can change between runs. Earlier runs during development produced slightly different names and splits. Anyone who needs stable folders can set a fixed list in the config file, and the model will then only file videos into it.

Captions, hashtags, author handles and a few low-resolution frames are sent to an external model provider. That was acceptable for my own library. A stricter setup can point the tool at a locally hosted model. No video in this run had a transcript, so videos where the meaning is only in the speech are still under-described.

Instagram has no official API for saved posts. The collector uses the private mobile API, which goes against the platform's terms and is rate limited. I use it only on my own account, slowly, and reuse the saved login session.

Code and privacy

The source code is public: github.com/RuddiRodriguez/igvault. The repository contains code and configuration only. The README explains how to set it up, the settings and the classifier design.

No videos, captions, transcripts, account names, login sessions or API keys are published here or in the repository. This article reports only aggregate counts and topic names, and the examples are paraphrased without naming any account.
