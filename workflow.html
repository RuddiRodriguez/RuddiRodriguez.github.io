NEW PROJECT

Python · Model development

02 / TABULAR CLASSIFIER FLOW

One workflow.
Different prediction problems.

A reusable workflow that takes a table of data through model comparison, tuning, validation, and an interactive dashboard. Adapt it to a new yes-or-no prediction problem by changing project settings.

01

Prepare data

Split a CSV table into training and test data, with repeatable settings.

02

Compare models

Compare candidate models across repeated training and validation splits.

03

Refine candidates

Refit the leading models, compare their scores, and save candidate pipelines.

04

Tune and train

Search model settings with Optuna and save the best tuned pipeline.

05

Validate

Score test data and export metrics, cutoff comparisons, ranked predictions, and charts.

06

Explore results

Inspect datasets and models in a Streamlit dashboard, with optional feature-importance reports.

WHY I BUILT IT

Reuse the process.

Different prediction problems share many steps. This project puts data paths, target labels, model settings, and reporting choices in one configuration file so the same scripts can support another dataset.

The documented example uses credit-card fraud data. The workflow also includes generated response-model data for demonstrations.

WHAT MAKES IT USEFUL

Comparison through reporting.

  • Compare several models before selecting candidates for tuning.
  • Keep preprocessing and the fitted model together in a saved pipeline.
  • Adjust evaluation measures and selection rules through project settings.
  • Choose datasets and saved models in the dashboard, then explore their results.

DELIVERABLES

A complete set of model artifacts.

  • Training and test datasets
  • Model comparison tables
  • Saved candidate pipelines
  • Tuned model and parameters
  • Validation reports and charts
  • Interactive dashboard

ADAPTING TO ANOTHER PROJECT

Change settings, rerun the flow.

Set the input CSV, training and test paths, target column, and dashboard title. Add dashboard filters or extra model choices when needed.

SUPPORTED INPUT

Tables with a yes-or-no outcome.

Input must be a CSV table with the outcome encoded as 0 or 1. Models must work with scikit-learn. Adding a new model requires registering it and defining tuning choices when applicable.
