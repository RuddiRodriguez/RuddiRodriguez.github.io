Make the learning steps visible

The idea is to explore different machine learning algorithms by writing their calculations directly with NumPy. I want to see how a prediction is made, how its error is measured, and how the model changes to improve the next prediction.

Each example starts small so the connection between the maths and the code stays easy to follow. NumPy handles the numerical calculations. Matplotlib draws the results; the learning itself is written in Python and NumPy.

01 / Learning a straight line

The first example uses six illustrative pairs of study hours and test scores. The model predicts a score by multiplying the hours by a slope and adding an intercept. Both values start at zero.

To understand the update, I start with the equation of a straight line and work through the derivatives. A derivative tells us how the error changes when we slightly change one model parameter.

From the familiar line equation to the code

1. Write the prediction. For observation i, the line predicts ŷᵢ = w xᵢ + b. Here, xᵢ is the input, yᵢ is the observed score, w is the slope, and b is the intercept. The hat in ŷᵢ means “predicted”. There are n observations.

2. Define the error we want to minimise. The code uses the observed value minus the prediction: eᵢ = yᵢ − ŷᵢ. Square each error and average across all observations. This gives the mean squared error, written as L:

Squaring prevents positive and negative errors from cancelling and gives larger errors more weight. Dividing by n makes this an average.

3. Differentiate with respect to the slope. We change w while holding b fixed. This is a partial derivative, written ∂L/∂w. The chain rule says: differentiate the outside square, then multiply by the derivative of the error inside it.

The 2 comes from differentiating a square. The minus sign comes from subtracting the prediction in our definition of error. The xᵢ appears because changing the slope changes each prediction in proportion to its input.

4. Differentiate with respect to the intercept. Now change b while holding w fixed. Increasing the intercept by one increases every prediction by one, so the derivative of the error is −1:

5. Translate the sums into NumPy. The arrays contain all observations. x * error multiplies each input by its corresponding error, np.sum adds the terms, and len(x) supplies n. The code names the two derivatives dw and db:

Some explanations define the error as prediction minus observed value. With that convention, the gradients are written with +2/n. Both give the same derivatives when the error definition and sign are used consistently. This loss uses 1/n; a loss defined with 1/(2n) would cancel the factor of two.

6. Take a small step downhill. The two derivatives together form the gradient. They point towards increasing loss locally, so gradient descent subtracts them. The learning rate, written α, controls the step size:

A positive derivative makes the corresponding parameter decrease; a negative derivative makes it increase. Small enough steps move downhill, but an overly large learning rate can overshoot.

The first update, using the actual example

Initially, w = 0 and b = 0, so every prediction is zero and the errors equal the observed scores. With six observations, Σ xᵢeᵢ = 142.9 and Σ eᵢ = 34.1:

The line moves upwards from its initial zero predictions. For x = 1, its new prediction is approximately 0.59. Across all six observations, the mean squared error drops from approximately 37.6183 to 17.4701. The next iteration repeats the same calculations using the updated line.

The script measures the error again after each update. It stops when the change in error is smaller than the chosen tolerance, or when it reaches the iteration limit. Finally, it prints the fitted values and plots the line beside the data.

This example explores how the updates work and how the stopping rule behaves. The small dataset is illustrative; it does not establish a real relationship between studying and test performance.
