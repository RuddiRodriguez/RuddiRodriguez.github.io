DOCUMENT CONVERSION / PYTHON / AI VISION / QUALITY CHECKS

A PDF to Word pipeline that checks its own work

No single converter handles every PDF well. This pipeline tries the cheapest reliable method first, scores every page against the source, sends only failing pages to an AI vision model, and flags the rest for a person. Each client's style lives in a profile file, so the code stays the same between projects.

The problem with one converter

A direct converter can make a page look right while the Word file is hard to edit. On the sample report, the pdf2docx library rebuilt the page layout as 9 Word tables when the source has 1. An AI model reads difficult pages well but costs money per page and can drop or change text. OCR reads printed scans but not handwriting. Each method fails in a different place, so the method is chosen page by page, after measuring the result.

01

Prepare

Turn a PDF or a folder of photos into one PDF. A file with no text layer is a scan, so OCR adds one.

02

Convert

Try methods in order of cost: whole-file converter, rules-based extraction, then the AI vision model.

03

Score

Compare each page with the source text: word order, missing or added text, tables and changed numbers.

04

Fall back

Only pages that fail move to the next method. Pages that never pass keep their best attempt and are flagged.

05

Write

Every page becomes editable Markdown with cropped figures, then Word in the client's style.

06

Review

A person checks flagged pages side by side with the source. Edits rebuild the Word file with no new AI cost.

Methods, in order of cost

MethodUsed forCost

Code example: the page cascade

Each method runs only on the pages still pending. A page leaves the loop as soon as one method passes, so a 40-page report with three difficult pages sends three pages to the paid model, not forty.

The quality gate

A page that looks right in Word can still be an image, miss a paragraph, or change a number in a table. The gate measures those separately, from 0 to 1, against the text inside the PDF.

CheckQuestion
TextAre the same words there, in the same order?
EditableIs the amount of real text about the same, so nothing was lost inside an image or invented?
TablesDid tables survive as real Word tables?
NumbersIs any number missing or new? Any difference flags the page, whatever the score.

Scans: two independent readers

A scan has no true text to compare against. My first version scored rules-based extraction against the OCR text it had just read, so every scanned page passed with a perfect score. That check proved nothing. Now the AI model transcribes from the image alone, and the OCR text is used only to check it. When the two readers agree, the page passes. When they disagree, a person checks the page. If the AI step is switched off for confidential work, every scanned page is flagged.

Charts caused the next false alarm. OCR read chart lines as stray characters while the AI model described the chart labels, so the two readers disagreed on chart pages even when the body text was right. The model now marks each figure's position, the figure is cropped into Word as an image, and text inside it is left out of the check. On the scanned test, the two chart pages went from 0.64 and 0.55 to 1.00 agreement.

One pipeline, many clients

What changes between clients is a small JSON profile, not the code: font, spacing, page size, OCR language, lines to remove such as running headers, the pass threshold, and which methods may run.

Every page is saved as Markdown before Word is written. A reviewer fixes a page in a text file and runs one rebuild command. Their edits are never overwritten, and AI answers are cached by image, model and prompt, so reruns do not pay twice.

What this does not establish

  • The scores compare the result with the PDF's own text. On scans they measure agreement between two readers, not accuracy against a corrected transcript.
  • Handwriting still needs a person. OCR cannot read it, so there is no second reader, and the AI model misread words and one number in my handwritten test.
  • Text inside charts stays part of the chart image. Equations and complex layouts are not rebuilt.
  • The pipeline was tested on a small set of documents. Thresholds should be checked on a client's own sample pages before a large job.
