REAL INPUT OR DEMONSTRATION DATA

Two starting points.

Existing datasets enter through a CSV reader. A separate generator creates fictional campaign contacts, repeated customer histories, previous response information, and a configurable response rate.

The generator uses a fixed seed for repeatable demonstrations. Its outcome column is named Responsflag; the campaign demonstration needs matching project settings.

TRAINING AND TESTING

Keep the outcome balance.

The current settings reserve 20% of records for testing and 80% for training. The split keeps roughly the same proportion of each outcome in both sets and writes separate CSV files.

This is a random split of rows. It does not separate customers or reserve a later time period.

NUMBERS AND CATEGORIES

Prepare each column type.

Numeric columns are put on a common scale. Text categories receive numeric codes, with a reserved value for categories not seen during fitting.

These transformations are fitted as part of the model pipeline and reused when scoring new records.

REPEATABLE HANDOFF

Ready for model comparison.

The prepared workflow produces training and test tables, plus a reusable preprocessing pipeline. The split script reports row counts and the outcome rate in each set.

That creates the starting point for comparing candidate models—the next part of the same project.

NEW PROJECT

Python · Model development

02 / TABULAR CLASSIFIER FLOW

One workflow.
Different prediction problems.

A reusable workflow that takes a table of data through model comparison, tuning, validation, and an interactive dashboard. Adapt it to a new yes-or-no prediction problem by changing project settings.

01

Prepare data

Split a CSV table into training and test data, with repeatable settings.

02

Compare models

Compare candidate models across repeated training and validation splits.

03

Refine candidates

Refit the leading models, compare their scores, and save candidate pipelines.

04

Tune and train

Search model settings with Optuna and save the best tuned pipeline.

05

Validate

Score test data and export metrics, cutoff comparisons, ranked predictions, and charts.

06

Explore results

Inspect datasets and models in a Streamlit dashboard, with optional feature-importance reports.

WHY I BUILT IT

Reuse the process.

Different prediction problems share many steps. This project puts data paths, target labels, model settings, and reporting choices in one configuration file so the same scripts can support another dataset.

The documented example uses credit-card fraud data. The workflow also includes generated response-model data for demonstrations.

WHAT MAKES IT USEFUL

Comparison through reporting.

  • Compare several models before selecting candidates for tuning.
  • Keep preprocessing and the fitted model together in a saved pipeline.
  • Adjust evaluation measures and selection rules through project settings.
  • Choose datasets and saved models in the dashboard, then explore their results.

DELIVERABLES

A complete set of model artifacts.

  • Training and test datasets
  • Model comparison tables
  • Saved candidate pipelines
  • Tuned model and parameters
  • Validation reports and charts
  • Interactive dashboard

ADAPTING TO ANOTHER PROJECT

Change settings, rerun the flow.

Set the input CSV, training and test paths, target column, and dashboard title. Add dashboard filters or extra model choices when needed.

SUPPORTED INPUT

Tables with a yes-or-no outcome.

Input must be a CSV table with the outcome encoded as 0 or 1. Models must work with scikit-learn. Adding a new model requires registering it and defining tuning choices when applicable.

THE QUESTION

Who should we select?

A response score alone does not tell us how many records to select, how many positive responses we might capture, or how many incorrect selections we might make.

This workflow examines those choices at different score cutoffs and at different sizes of the highest-ranked group.

THE APPROACH

Look beyond one metric.

  • Measure correct predictions, missed positives, and incorrect selections.
  • Compare precision and recall: how reliable selections are, and how many positives they capture.
  • Review lift and gain: how ranking compares with selecting without a model.
  • Inspect probability calibration when probability scores are available.

WHAT THE WORKFLOW PRODUCES

Reports you can inspect.

  • Validation metrics
  • Score-cutoff comparison
  • Top-ranked selection summary
  • Ranked predictions
  • Lift and gain tables
  • Static and interactive charts
