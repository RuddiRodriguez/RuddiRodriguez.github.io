A result depended on which rows I held back

My first experiments could fit a model and print a report. The next question was how to compare results across more than one division of the examples. Cross-validation became part of that progression.

Instead of reserving one group once, cross-validation divides the data into several folds. The classifier trains on the other folds and predicts the held-back fold, then repeats until each fold has served as validation data. It gives a view across those repeated fits.

The first repeated evaluation

cross_val_predict returns a held-back-fold prediction for each row. The script compares those predictions with the known labels and prints accuracy and a per-class report. Here cv=3 asks for three folds.

There is an important detail in the order: the vocabulary is fitted before cross-validation. The classifier is held back from each validation fold, but the vocabulary has already seen the full supplied collection. This evaluates only part of the learning procedure independently.

Word extraction had to travel with the model

The vocabulary is learned from data too. It determines which word columns exist, and TF-IDF also learns collection-level frequencies. For a comparison of the complete procedure, those steps need to learn from each fold’s training text.

The later search puts CountVectorizer and the classifier in the same Pipeline. Cross-validation then fits that combined object inside each fold:

This changed the unit being evaluated. Each candidate became “learn the word representation, then fit this classifier,” rather than “fit a classifier on a matrix built beforehand.” The pipeline also gives prediction the fitted representation used during training.

This search pipeline still receives text prepared outside the search. The later shared workflow moves the cleaning operations into its connected process as well. Those are related changes, but they happen at different points in the archive.

Which score should guide the comparison?

The searches record macro precision, macro recall, macro F1, and balanced accuracy. Macro means averaging the class-level scores equally. This matters because Mid-Senior level has far more rows than Executive or Associate.

The refit choice is recall_macro: select the candidate with the strongest average recall across the six levels, then fit it on the supplied training data. That makes the selection rule visible rather than leaving the meaning of “best” implicit.

Cross-validation does not remove repeated descriptions. Copies split across folds still weaken the independence of the evaluation. The closing article keeps that data question alongside the historical results.

Now I could compare the settings systematically

Once the word representation belonged to the model being evaluated, vocabulary choices could be searched alongside classifier settings. The next chapter follows the move from fixed choices to those joint experiments.
