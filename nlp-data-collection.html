Before a model, I needed examples

The seniority labels were already attached to the job advertisements. That gave me a practical starting point: collect the description and its label together, save the records, and use them for supervised learning—a model trained on examples with known answers.

The collection script searched for data-science jobs. It first read search-result pages to find job identifiers, then visited each job page to extract its description and criteria. Collection and classification were separate stages; the model did not fetch advertisements while making a prediction.

From result pages to individual descriptions

The page offset changes by ten on each request. The collected identifiers become the input to the second loop. Filtering to numeric identifiers removes values that do not look like job IDs; it does not remove repeated IDs.

A collected row is not always a different advertisement

Looking back at the files, the labelled training rows contain only 183 distinct exact description strings. The separate evaluation file contains 1,325 labelled rows and 87 distinct descriptions. Ten exact description strings occur in both files.

Those are counts from the archived files, not a new scrape. Repetition matters because another row can carry text the model has already seen. A random row split can put copies of the same description on both sides of the evaluation.

The archive shows the repetition but does not establish the origin of every repeated row. I would keep a stable advertisement identifier and collection date when rebuilding the dataset, then define how repeated or reposted descriptions belong in the split. The final chapter returns to what this means for the saved results.
